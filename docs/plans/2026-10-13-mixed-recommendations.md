# 多端混合推荐实施计划

**Goal:** 落实已获用户批准的混合内容池、兴趣排序、20% 探索、近期去重和稳定会话推荐。

**Architecture:** 纯 JavaScript 推荐核心由 Node 本地服务与 TV QuickJS 共同运行。远程仅同步资料及显式偏好，不依赖远程才能推荐。每个播放会话携带独立随机 session ID，分页结果可重试且已发内容不重复。

**Tech Stack:** Node SQLite、Kotlin/Android SQLite、QuickJS、React、现有家庭同步协议。

### 1. 共用规则和本地服务
新增共享推荐排序模块及测试。候选来自三种官网分类热门、最新和兴趣题材；默认配比 50/30/20，至少 20% 探索，七天观看降权、全剧完播默认排除。稳定种子打破同分，每次新会话种子不同。来源失败用可用类型补足，首屏不等待所有来源。会话分页去重、过期及并发请求保护。

### 2. 同步资料契约
扩展 recommendation 资料和 recommendationMode/recommendationResetAt 显式偏好。信号累计有效播放毫秒、曝光、主动快速跳过及全剧完成；快退、暂停、后台和错误不产生跳过。保留现有删除与重置语义，更新同步校验及管理平台兼容。

### 3. Web/电脑接入
独立会话 ID、推荐分页、有效观看信号、设置内容模式与重置偏好。保留继续观看独立入口，普通推荐从第一集开始；取消旧请求不覆盖新会话。

### 4. TV 接入
加载共享核心，独立引擎候选及资料快照。遥控器切剧信号与实际播放累计，设置模式/重置，API 22 兼容并保持 UI 响应。

### 5. 验证与交付
规则、重复分页、失败补足、时钟、信号、同步与偏好回归；Web 构建、Node 测试、Android 测试/lint/APK。实机检查混合类型、重启变化、会话返回和快进暂停不误判。更新运行服务、独立包及交接文档。

执行使用 subagent-driven-development：根代理负责共享核心和 Node 推荐；资料契约、Web 接入、TV 接入由互不重叠的实现任务完成，然后统一审查验证。不提交已有未提交的迁移工作。
