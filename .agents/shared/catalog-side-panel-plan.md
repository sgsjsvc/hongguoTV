# 分类页改造为左侧双列筛选栏 — 方案

**协调者**: dsh
**日期**: 2026-10-15
**范围**: **仅 TV 端**，**仅分类页**（排行榜不动）
**用户需求**：

> 将分类列表改造右侧列表方式显示，排行榜也是如此。该方案只针对 TV 端
>
> **更正**：不好意思，是左侧，两列一列显示剧的分类，一列显示题材分类，不可折叠，占有左侧宽度尽可能的小
>
> **排行榜不动（保留平铺）**

## 一、问题（实测证据）

### 实测数据（`emulator-5554`，1280×720）

来自既有 dump（`outputs/debug/official-tv-category.xml`）与截图（`.agents/shared/u4-category.png`）：

| 区域 | y 范围 | 高度 |
| --- | --- | --- |
| 标题「分类」 | 24–64 | 40px |
| 一级类型（真人剧/漫剧/AI剧） | 64–120 | 56px |
| **题材标签（25 个）** | **120–232** | **112px** |
| 网格卡片 | 240–585 | 345px |

**筛选区占 232px**，网格可用高度仅 **488px** —— 只能显示 **1 行完整卡片**。

### 截图目视确认（`.agents/shared/u4-category.png`）

- 题材标签占 **3 行**，第三行只有「剧情」**一个孤立标签**
- 网格只露出 **1 行**卡片，底部被裁切
- 「加载更多」按钮占据屏幕下方大量空间

### 核心矛盾

`CategoryTagLayout` 的设计注释：

```kotlin
/** All filters stay visible; wrap to the available TV width without horizontal scrolling. */
```

「所有筛选保持可见」在 **24 个题材标签**（实测 API 返回 24）时，**直接挤占内容展示空间**。

## 二、方案：左侧双列竖向筛选栏

### 布局对比

**改造前**：

```
┌─────────────────────────────────────────┐
│ 分类                                    │
│ [真人剧][漫剧][AI剧]                    │
│ [全部题材][爱情][年代][逆袭]...[剧情]   │ ← 3 行，232px
├─────────────────────────────────────────┤
│ ┌────┐┌────┐┌────┐┌────┐┌────┐          │
│ │卡片││卡片││卡片││卡片││卡片│          │ ← 仅 1 行
│ └────┘└────┘└────┘└────┘└────┘          │
│         [加载更多 · 第 1 页]            │
└─────────────────────────────────────────┘
```

**改造后**（左侧双列）：

```
┌────────┬────────┬───────────────────────┐
│ 类型   │ 题材   │ 分类                  │
│        │        │ ┌────┐┌────┐┌────┐    │
│▸真人剧 │ 全部题材│ │卡片││卡片││卡片│    │
│ 漫剧   │ 爱情   │ └────┘└────┘└────┘    │
│ AI剧   │ 年代   │ ┌────┐┌────┐┌────┐    │
│        │ 逆袭   │ │卡片││卡片││卡片│    │
│        │ 传奇   │ └────┘└────┘└────┘    │
│        │ 成长   │ ┌────┐┌────┐┌────┐    │
│        │ 家庭   │ │卡片││卡片││卡片│    │
│        │ ...    │ └────┘└────┘└────┘    │
│        │ (滚动) │      [加载更多]       │
└────────┴────────┴───────────────────────┘
```

### 收益

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 筛选区垂直占用 | 232px | **0** |
| 网格可用高度 | 488px | **720px** |
| 可见卡片行数 | 1 行 | **2–3 行** |
| 左侧栏占屏宽 | — | **约 17–19%** |

## 三、详细设计

### 3.1 结构

`CatalogScreenView` 根布局从纯 `LinearLayout(VERTICAL)` 改为：

```
LinearLayout(VERTICAL)                      ← 根
└── LinearLayout(HORIZONTAL)                ← 新增：左右分栏
    ├── 左栏（固定宽，仅 category 显示）
    │   ├── 类型列（3 个按钮，竖向）
    │   └── 题材列（ScrollView + 25 个按钮，竖向）
    └── 右区（weight=1f）
        ├── 标题
        ├── RecyclerView 网格
        └── 加载更多按钮
```

**注意**：标题移到右区（原在顶部整行），避免左栏上方留空。

### 3.2 左栏规格（「宽度尽可能小」）

**列宽计算**：

| 项 | 值 |
| --- | --- |
| 最长标签 | **「动作冒险」4 字**（实测） |
| 文字尺寸 | 13f |
| 文字宽 | 4 × 13 = 52dp |
| 左右 padding | 各 6dp → 12dp |
| **单列宽** | **64dp** |
| 列间隙 | 6dp |
| 外层 padding | 各 6dp → 12dp |
| **左栏总宽** | **146dp** |

**占屏比**：146 / 853 = **17%**（720p 档）

**新增 dimens 键**（三档）：

| 键 | values | sw600dp | w1280dp |
| --- | --- | --- | --- |
| `catalog_rail_width` | 130dp | 146dp | 175dp |
| `catalog_rail_pad` | 5dp | 6dp | 8dp |
| `catalog_rail_gap` | 5dp | 6dp | 8dp |
| `catalog_rail_btn_height` | 32dp | 36dp | 42dp |
| `catalog_rail_btn_text` | 12sp | 13sp | 15sp |

### 3.3 题材列滚动

25 个题材标签竖向排列：

| 项 | 值 |
| --- | --- |
| 单按钮高 | 36dp + 间隙 6dp = 42dp |
| 左栏可用高 | 480 − 32(padding) = 448dp |
| 可见数量 | 448 / 42 ≈ **10 个** |
| 需滚动 | 是（25 个） |

**实现**：题材列外层套 `ScrollView`（垂直），类型列**不滚动**（仅 3 个）。

**焦点要求**：题材按钮获焦时需自动滚动到可见区域（Android `ScrollView` 默认行为，需实测确认）。

### 3.4 网格列数

左栏占 146dp 后，网格宽度从 853dp → 707dp：

| 列数 | 每列宽 | 评价 |
| --- | --- | --- |
| **4 列** | 177dp | 卡片明显变大 |
| **5 列** | 141dp | 接近原尺寸（158dp） |

**建议保持 5 列**（每列 141dp，卡片略小但一屏可见更多剧）。

> `GridLayoutManager(context, 5)` 目前硬编码（`CatalogScreenView.kt:135`），保持不变即可。

### 3.5 视觉分组

两列并排时需区分「类型」与「题材」：

| 方案 | 说明 |
| --- | --- |
| **A. 列内小标题** | 各列顶部加「类型」/「题材」小字 |
| **B. 分隔线** | 两列之间加竖线 |
| **C. 颜色区分** | 类型用不同底色 |

**推荐 A** —— 占用高度小（约 20dp），语义清晰。

### 3.6 排行榜不动

`source == "rank"` 时**保持现状**（顶部平铺，U6 方案）：

```kotlin
if (source == "rank") { /* 保持现有 HorizontalScrollView 平铺 */ }
```

左栏**仅在 `source == "category"` 时显示**。

## 四、风险与约束

### 4.1 焦点流转（最高风险）

现状（`MainActivity.kt:1177`）：

```kotlin
filter?.requestFocus() ?: rankBtn?.requestFocus() ?: tool?.requestFocus()
    ?: (manager.findViewByPosition(index)?.requestFocus() ?: grid.requestFocus())
```

**改造后需保证**：

1. 左栏按 **RIGHT** → 进入网格
2. 网格按 **LEFT** → 回到左栏
3. 类型列与题材列之间按 **LEFT/RIGHT** 正确流转
4. 切换筛选后焦点**留在原按钮**（便于连续切换）
5. 首次进入页面焦点落点合理

**参考**：`PlayerOverlay.kt:224-233` 用了 `nextFocusLeftId` / `nextFocusRightId`。

### 4.2 左栏两列的焦点顺序

两列并排时，Android 默认焦点搜索可能不按预期。

**建议显式设置** `nextFocusRightId` / `nextFocusLeftId`。

### 4.3 空态

`CatalogScreenView.kt:128-133` 的空态逻辑（「返回推荐」按钮）需同步调整。

### 4.4 既有技术债

`series_card_width` 键名实际表示**高度**（`SeriesAdapter.kt:44`）。本次涉及网格尺寸，**建议一并重命名为 `series_card_height`**。

## 五、验收标准

1. **左栏双列**：类型列 + 题材列，竖向排列
2. **宽度占比**：≤ 20%（720p 下 ≤ 170dp）
3. **不可折叠**：常驻显示
4. **题材列可滚动**：25 个标签可完整访问，获焦项自动可见
5. **网格高度**：从 488px 增至 ≥ 650px，可见 ≥ 2 行卡片
6. **焦点**：LEFT/RIGHT 在左栏与网格间正确流转；两列间流转正确
7. **切换筛选**：焦点留在按钮，列表正常刷新
8. **排行榜**：**保持 U6 顶部平铺，无变化**
9. **其他页面**：favorites / history / search **无变化**
10. **三档分辨率**：720p / 1080p / 4K 布局均正确
11. **构建**：`assembleDebug`、`lintDebug`、`testDebugUnitTest` 通过
12. **截图证据**：三档分辨率 × 分类页；排行榜对比截图（证明未变）
