# A2 HEVC Level 与编码抽样报告

执行方 codex；日期 2026-10-15（Asia/Shanghai）。任务 t-a2-hevc-survey。仅只读分析，未修改业务代码或操作设备。

## 结论

1. 实测 24 部不同剧集、36 个档位样本，主样本 HEVC Level 分布为 {"6.2":24}；结果只适用于本次榜单抽样，不代表全站概率。
2. 实际 MP4 stsd/hvcC/avcC 检查未发现 AVC；模型记录的 codec_type 计数为 {"bytevc1":76,"bytevc2":44}。bytevc2 是另一类编码声明，未将它归入 HEVC，也未将它误写为 AVC。
3. 三部完整跨档位样本所有可用档位逐个取流，见下表；本轮范围内 Level 与分辨率未表现为同步变化。
4. 原始 hvcC 声明由 ffprobe 独立交叉验证；帧率取值 30/1、25/1、24/1。配置中的 Level 6.2 不等于实际视频是 8K：它是解码能力声明，低分辨率也可以携带高 Level。不能只据分辨率断言一律改成 120 安全。

## 方法与范围

来源为官网 hot-drama、hot-real-drama、hot-comic-drama、hot-ai-drama 各第一页，轮询去重取样，选择首集、最高可用非 bytevc2 档位为主样本。实际读取 CDN 原始 MP4，未经过我方解密头部改写。每次媒体请求间隔至少 750ms，串行执行；不保存媒体 URL、访问头或解密密钥。

读取起始 262144 字节；若 moov 大于前缀，仅追加读完 moov，限定 8MiB。按 ftyp/moov/trak/mdia/minf/stbl/stsd 的真实 box 边界解析，encv/enca 通过 sinf/frma 恢复原始编码声明，避免直接搜索四字符造成误判。hvcC level 字节为 payload+12，即 box起点+20，或字符串 hvcC 起点+4+12；profile 是 payload+1 低5位。任务说明中的不同 offset 基准在这里统一。

取样开始 2026-10-15T03:30:24.613Z，结束 2026-10-15T03:34:00.861Z；共享引擎 SHA256 fa81f05ce204413b529f9b121b4a398dec0b809dfb0fc7ab6a5e642a808cfa63。分析使用内存加载的该版本，之前榜单改动保持原样。

## 补充参数集检查

另检查 hvcC 内 VPS/SPS，移除 emulation-prevention 字节后读取 profile_tier_level。VPS general_level_idc 集合 [186]，SPS 集合 [186]。完整逐文件证据 t-a2-parameter-set-check.json。实际修复若修改 Level，应检查容器 hvcC 与 VPS/SPS 的一致性，不能只改一个容器字段后就认定解码器必然接受；是否恢复硬解由 A1/DSH 设备测试决定，本任务未验证。

## 失败与重试记录

原始数据保留 11 条历史错误事件，不隐去。首轮扫描器要求 moov 完整存在于 256KiB 内，导致较大头部未解析；确认首例 moov=283310 字节后，改为追加读取剩余 moov。这是采样工具的读取边界问题，不能归因为上游取流失败。

补读后的最终样本均已成功，原始 JSON 的 previousErrors/failures 保留首轮记录。

## 复核命令与资料

~~~powershell
node .agents/shared/hevc-survey.mjs
node .agents/shared/hevc-survey.mjs --complete
node .agents/shared/hevc-survey-report.mjs
~~~

首轮确认 moov 边界后中止自有采样进程，保留 outputs/hevc-survey/first-pass.json，从逐条持久化检查点继续，不重复已有成功媒体样本。补采模式仅修复已尝试样本并补齐三部全档位。

原始数据：.agents/shared/t-a2-survey-data.json；参数集复核：.agents/shared/t-a2-parameter-set-check.json；本地二进制前缀及 SHA256 对照：outputs/hevc-survey/*.bin。日志 outputs/hevc-survey-run.log、hevc-survey-resume.log、hevc-survey-complete.log。JSON 未保存上游临时 URL、签名头和密钥。

Level 是 decoder requirement，编码器需综合码率等参数满足目标 Level，而非只由分辨率决定，参见 [x265 官方文档](https://x265.readthedocs.io/en/master/cli.html#profile-level-tier) 与 [ITU-T H.265 官方规范](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-H.265-201802-S%21%21PDF-E&lang=e&type=items)。本次统计不能独立证明「所有硬解均回退软解」或「降低 Level 后即可解决音画不同步」。
