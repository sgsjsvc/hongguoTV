# 性能发现：每秒轮询 /api/library（每天 1.2 GB）

**发现方**: dsh
**日期**: 2026-10-16
**方法**: 代码审查 + 实测（`scripts/perf/measure-polling-live.mjs`）

---

## 一、问题

**位置**：`apps/web-pc/src/api.ts:72`

```javascript
if (!migrationOnly) {
  setInterval(() => void refreshLibrary().catch(() => {}), 1000);   // ← 每秒一次
  window.addEventListener("online", () => void refreshLibrary().catch(warning));
}
```

**行为**：**无条件每秒请求 `/api/library`**。

**唯一的保护**是并发去重：

```javascript
export async function refreshLibrary() {
  if (refreshInFlight) return refreshInFlight;   // 只防并发，不防重复
  ...
}
```

**没有「数据未变化则跳过」的判断。**

---

## 二、实测数据

模拟前端轮询 10 秒：

| 指标 | 值 |
| --- | --- |
| 请求数 | **10 次 / 10 秒**（确认每秒 1 次） |
| 平均耗时 | 2 ms |
| 单次响应 | **14.2 KB** |
| 10 秒流量 | 142.3 KB |
| **每小时** | **50.0 MB** |
| **每天** | **1201 MB** |

### 响应体内容

`/api/library` 返回**完整 library**：

- 收藏列表
- 历史记录
- 推荐偏好
- 同步状态

**随用户数据增长而变大**（14.2 KB 是当前测试数据量）。

---

## 三、影响

| 场景 | 影响 |
| --- | --- |
| **播放视频时** | 每秒额外一次请求，与视频流争用连接 |
| **电视常开** | 每天 1.2 GB，长期运行显著 |
| **移动端/流量受限** | 持续消耗流量 |
| 服务器负载 | 每个客户端每秒 1 次请求 |

**对比**：1080P 码率约 3 Mbps，轮询占 **0.12 Mbps（3.9%）** —— 单看比例不大，
但**每秒一次固定请求**在长时间运行下累积明显。

---

## 四、为什么这样设计

推测原意：**保持多端同步的实时性** —— 另一台设备改了收藏，本端 1 秒内可见。

**但这代价过高**：

- 绝大多数轮询**没有数据变化**
- 真正的同步需求可以用**事件推送**或**按需拉取**满足

---

## 五、改进方向

| # | 方案 | 收益 | 复杂度 |
| --- | --- | --- | --- |
| 1 | **拉长间隔**（1s → 10s 或 30s） | 流量降 90–97% | 低 |
| 2 | **页面不可见时暂停**（`document.hidden`） | 后台不消耗 | 低 |
| 3 | **播放视频时暂停或降频** | 不与视频争用 | 低 |
| 4 | **条件请求**（ETag / If-Modified-Since） | 无变化返回 304 | 中 |
| 5 | **轻量增量接口**（只返回变更） | 响应体从 14 KB 降至几百字节 | 中 |
| 6 | **服务端推送**（SSE / WebSocket） | 实时且零轮询 | 高 |

**建议组合**：方案 2 + 3 + 4（低成本，覆盖大部分收益）

**最低成本改动**：方案 1 + 2 + 3（纯前端，无接口变更）

---

## 六、验收方式

**改进后应满足**：

| 项 | 目标 |
| --- | --- |
| 页面隐藏时 | 无请求 |
| 播放视频时 | 无请求或显著降频 |
| 空闲时（可见） | 间隔 ≥ 10 秒 |
| 数据变化时 | 仍能及时同步（≤ 10 秒延迟可接受） |

**测量脚本**：`scripts/perf/measure-polling-live.mjs`

---

## 七、注意事项

1. **不要破坏同步实时性** —— 用户期望改收藏后另一台设备能看到
2. **TV 端是否有同样轮询？** 需确认（本任务只覆盖 Web/Windows）
3. **`refreshLibrary` 被多处调用** —— 改间隔时注意别影响主动刷新路径
4. **测试时注意**：改间隔后需验证「主动刷新」（如用户点收藏）仍然立即生效
