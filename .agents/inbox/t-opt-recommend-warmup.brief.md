## 一、问题一：新会话推荐首屏冷启动 1.27–2.55 秒（DSH 实测）

| 场景 | 实测 |
| --- | --- |
| **新会话首屏（冷）** | **1274–2545 ms**（两次：3 / 2545) |
| 同会话重复（热） | **1 ms** |
| health / banners / sections | 5–40 ms（正常） |

**根因方向**：`hot:recommend:${session}:${page}` 缓存**按 session 隔离** →
**每个新会话都必然冷启动**一次数据池加载。而用户每次重开 App、或推荐偏好变化
（`needsRestart` 分支，见 `perf-drama-switch-analysis.md`）都会产生新会话。

**用户可感知**：首次进入推荐流等 1.3–2.5 秒；切剧若触发会话重建（既有分析测得 ~4 秒）更久。

## 二、必须做

### 2.1 冷启动预热（必须）

1. **先测量定位**：新会话首屏的 1.3–2.5 秒具体花在哪（上游数据池 `loadRound`？内容解析？）
   —— 用 `HG_TIMING=1` 或临时插桩分离
2. **预热方案**（评估后择一或组合，说明取舍）：
   - **服务启动时后台预热**推荐数据池（`custom-server/index.mjs:1010` 已有 `fetchOfficialHome()` 预热先例）
   - **跨会话复用数据池**：若数据池本身与 session 无关，则不应每会话重建（**优先排查此项**，可能是最大浪费）
   - 预热须**可关闭**（环境变量），且不得拖慢服务启动
3. **不得**通过放宽会话校验（`invalid recommendation session`，要求 `^[-_A-Za-z0-9]{16,128}$`）来"优化"

### 2.2 推荐质量测量（**先测量，不要凭感觉调参**）

**前提认知**：`append()` 性能经 B7 优化后 P95 = **1.03 ms**（DSH 独立复跑 3 次），
**算法性能已不是瓶颈**。本任务**不做性能优化**，只做**质量的测量与（必要时）调优**。

1. **建立质量基线**（只读测量，输出数据不要结论先行）：
   - 新会话首屏的**内容类型分布**（真人剧/漫剧/AI剧 三类是否都有）
   - **题材多样性**（不同 tag 数量）
   - **同页/跨页重复率**
   - **探索比例实际值**（代码声称 20%，实测是否为 20%）
   - **近期观看降权**是否生效（用有历史的会话对比无历史会话）
   - 翻页**顺序稳定性**（同会话重试是否稳定、新会话是否换序）
2. **仅在测量发现明确问题时**才提出调优方案，并给出**可验证的验收指标**与**回归测试**
3. ⚠️ **不得**为了提高"多样性"而破坏既有已验收语义（20% 探索、marked 优先、完播排除、
   近期降权、分页稳定、新会话换序）—— 这些已由 B7 验收，改动必须说明理由并补回归测试
