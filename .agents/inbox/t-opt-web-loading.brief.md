## 一、问题（DSH 实测）

后端延迟确实存在（新会话推荐 1.3–2.5 s、详情未预取 3.3 s、**取流首块最坏 12 s**），
但**前端的反馈更成问题**：

| 检查项 | 实测 |
| --- | --- |
| `apps/web-pc/src` 中**骨架屏**（`skeleton`/`Skeleton`/`animate-pulse`） | **0 处** |
| `apps/web-pc/src` 中 **loading 文案**（`加载中`/`loading`/`Loading`） | **0 处** |

**结论**：等待 1.3–12 秒期间，**用户看不到任何加载反馈** ——
这是"卡顿等待"感受的**主要来源**（后端 O1/O2 由 codex 并行修复，但感知层必须本任务补齐）。

> 说明：后端延迟优化（`t-opt-stream-latency` / `t-opt-recommend-warmup`）由 codex 负责；
> **本任务不改后端**，只做前端加载体验。

## 二、必须做

### 2.1 加载反馈（必须，逐页覆盖）

为以下**每个异步加载点**补加载态（骨架屏优先，其次 spinner/进度）：

| 页面/组件 | 需要的加载态 |
| --- | --- |
| 首页 / 推荐流首屏 | 卡片骨架屏（与真实卡片同尺寸，避免布局跳动） |
| 分类页 | 分类标签 + 海报网格骨架屏 |
| 榜单页 | 榜单列表骨架屏 |
| 搜索页 | 搜索中态 + 无结果态 |
| 详情页 | 详情信息 + 选集列表骨架屏 |
| 追剧/收藏页 | 列表骨架屏 |
| **播放器起播** | **明确的"正在加载视频"态**（首块可能等数秒，**必须有可见反馈**） |
| 清晰度切换 | 切换中态 |

### 2.2 错误态与重试（必须）

- 网络失败/超时：显示**明确的错误信息 + 重试按钮**，**不得**伪装成空列表
- 区分「空数据」与「加载失败」（当前若两者不可区分，须修正）
- 播放失败：明确提示（不要静默）

### 2.3 首帧与体感优化（建议）

1. **首屏关键路径**：确认首屏不阻塞在非关键资源上（当前 B8 已做分包，核对是否还有高优先阻塞）
2. **避免布局跳动（CLS）**：骨架屏尺寸与最终内容一致
3. **播放器提前准备**：进入详情页时即可发起取流准备（与后端预取配合，**不改后端**）
4. **进度可视化**：12 秒级等待应有进度感（不确定进度可用动画，但必须"有反应"）

### 2.4 不改行为语义

- **不得**改变任何既有业务交互语义（仅增加加载/错误反馈层）
- **不得**为"看起来快"而隐藏真实错误或伪造数据
